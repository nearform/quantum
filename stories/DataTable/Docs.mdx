# Data Table

Quantum does not ship a Data Table component. A data table is a Quantum [Table](?path=/docs/components-table--docs) whose rows, sorting, filtering, selection and paging are handled by [TanStack Table](https://tanstack.com/table/latest) v9. TanStack Table is headless: it holds the table state and gives you the rows to render, and the markup is built from Quantum components. This page shows how to put the two together, following the approach of the [shadcn/ui data table](https://ui.shadcn.com/docs/components/data-table).

<Canvas of={DataTableStories.Default} />

## Installation

TanStack Table is not a dependency of `@nearform/quantum`. Add it to your own project:

```bash
npm install @tanstack/react-table
```

The example uses version 8.

## Structure

The example is one file, split into four parts:

- **Features**: a `tableFeatures()` call that registers the table features the example uses (sorting, filtering, column visibility, selection and pagination), their row models, the built-in `filterFns` and `sortFns`, and the type of each column's `meta`. TanStack Table v9 only includes what is registered here. Without `filterFns`, for example, the filter input updates its value but no rows are filtered out.
- **Data**: a `Payment` type and an array of rows. In a real app the rows usually come from an API.
- **Columns**: a `ColumnDef<typeof features, Payment>[]` array. Each column sets how its header and cells render. This is where Quantum components such as `Checkbox`, `Avatar`, `Badge` and `IconButton` are used.
- **`DataTableDemo`**: calls `useTable` with the features, the data and the columns, then renders the result into `Table`, `TableHeader`, `TableBody`, `TableRow`, `TableHead` and `TableCell`.

```bash
└── DataTableDemo
    ├── Input (filter)
    ├── Table
    │   ├── TableCaption
    │   ├── TableHeader
    │   │   └── TableRow
    │   │       └── TableHead (align, sortDirection, onSort)
    │   └── TableBody
    │       ├── TableRow (selected)
    │       │   └── TableCell (align, flexRender)
    │       └── TableEmpty
    ├── selection count
    └── Pagination
```

## How the Table props map to TanStack Table

The Table components have props for the parts every data table needs, so you only have to connect them to TanStack Table:

<table>
  <thead>
    <tr>
      <th scope="col">Table prop</th>
      <th scope="col">TanStack Table</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`TableHead sortDirection`</td>
      <td>`header.column.getIsSorted()`</td>
    </tr>
    <tr>
      <td>`TableHead onSort`</td>
      <td>
        `header.column.getToggleSortingHandler()`, when
        `header.column.getCanSort()` is true
      </td>
    </tr>
    <tr>
      <td>`TableRow selected`</td>
      <td>`row.getIsSelected()`</td>
    </tr>
    <tr>
      <td>`TableHead align` and `TableCell align`</td>
      <td>`column.columnDef.meta.align`</td>
    </tr>
    <tr>
      <td>`TableEmpty colSpan`</td>
      <td>
        `columns.length`, rendered when `table.getRowModel().rows` is empty
      </td>
    </tr>
  </tbody>
</table>

See the [Table docs](?path=/docs/components-table--docs) for what each prop does on its own.

## Features

### Alignment

TanStack Table lets each column carry extra data in `meta`. The example adds an `align` field there, set to `'right'` on the amount column, and passes it to both `TableHead` and `TableCell`. `align` is not a TanStack Table option, so the example declares its type in the `columnMeta` slot of `tableFeatures()`. Without that declaration TypeScript rejects the field.

### Sorting

Columns can be sorted unless they set `enableSorting: false`. `TableHead` renders the sort button, the direction icon and `aria-sort` itself, so the example only passes it `sortDirection` and `onSort`. Clicking a header cycles through ascending, descending and unsorted.

### Filtering

The `Input` above the table filters by customer name through `table.getColumn('name').setFilterValue()`. Typing in it or clearing it returns to the first page. To search every column instead, use `globalFilter` in place of a column filter.

### Row selection

The first column renders a `Checkbox` in the header and in every row. The header box selects all rows on the current page and shows the indeterminate state when only some are selected. Each row passes `row.getIsSelected()` to `TableRow selected`, which highlights it. Rows are keyed with `getRowId`, so a selection stays on the right row after sorting or filtering. A live region below the table announces how many rows are selected.

### Row actions

The last column opens a `Popover` from an `IconButton`. Put row-level actions such as edit, copy and delete there.

### Pagination

TanStack Table owns the page state. Quantum's `Pagination` is 1-based and TanStack Table is 0-based, so the example converts between them in `setCurrentPage`. The pagination is hidden when everything fits on one page.

<Canvas of={DataTableStories.Empty} />

When there are no rows, whether because the data is empty or the filter matches nothing, the example renders `TableEmpty` with `colSpan={columns.length}`. It shows "No results." in a single cell spanning every column.
