# Avatar

An avatar is a small, usually circular graphic that stands for a person, an
organisation or an account. It shows a picture when there is one to show, and
falls back to the initials of the name — or to a generic person icon — when
there is not.

### Default

Give the avatar a `name` and it renders the initials of the first and last
word, and announces the full name to a screen reader.

<Canvas of={AvatarStories.Default} />

### With an image

`src` layers an image over the initials. The initials stay underneath, so the
avatar never flashes empty while the image loads.

<Canvas of={AvatarStories.WithImage} />

### When the image fails

An image that cannot be loaded uncovers the fallback rather than leaving a
broken-image icon behind. Changing `src` retries.

<Canvas of={AvatarStories.BrokenImage} />

### Without a name

With no `name`, `alt` or `initials`, the avatar renders a person icon and is
hidden from assistive technology as decoration — the surrounding text is
expected to carry the name.

`initials` overrides the two letters derived from `name`, for an acronym or a

## Dark mode

The avatar reads its surface and text colour from the `background-alt` and
`foreground` tokens, both of which have a dark counterpart, so nothing extra is
needed — toggle the theme in the toolbar to see it. An image is untouched by
the theme; only the fallback changes.

## Accessibility

- The accessible name comes from `alt`, falling back to `name`. When an image
  is rendered it becomes the image's `alt` text; otherwise the avatar itself
  takes `role="img"` with that name.
- With no name of any kind the avatar is `aria-hidden`, which is the right
  answer for the common case of an avatar sitting next to the name it depicts —
  announcing it twice helps nobody.
- Initials are never announced on their own: "AL" is not a name. They are
  always inside the `aria-hidden` fallback layer.
- `role` and the generated name travel together. Passing a `role` of your own
  drops the `aria-label` the avatar would have added, so
  `<Avatar role="presentation" />` really is silent — a presentational element
  that still carries a name gets re-exposed by the browser. Pass your own
  `aria-label` alongside the role when you do want it named.

## Usage

```tsx
import { Avatar } from '@nearform/quantum'

// Initials, derived from the name
<Avatar name="Ada Lovelace" />

// Picture, with the initials as the fallback
<Avatar name="Ada Lovelace" src="/ada.jpg" size="lg" />

// Decorative, next to the name it depicts
<span className="flex items-center gap-2">
  <Avatar size="sm" />
  Ada Lovelace
</span>
```
